# Governance и управление рисками

## Реестр рисков (Risk Register)

| Риск | Вероятность | Влияние | Как обнаружить | Механизм защиты | Остаточный риск |
|-----|-----|-----|-----|-----|-----|
| Галлюцинации модели (неверные факты) | Средняя | Высокое | Проверка источников, тестовые запросы | Обязательные citations, указание confidence | Средний |
| Prompt Injection | Средняя | Высокое | Анализ входного запроса | фильтрация промптов, sandbox execution | Средний |
| Использование недостоверных источников | Средняя | Среднее | Анализ источников | ранжирование источников, reranker | Низкий |
| Утечка чувствительных данных | Низкая | Высокое | аудит логов | ограничение доступа, masking данных | Низкий |
| Высокая latency | Средняя | Среднее | мониторинг времени ответа | оптимизация pipeline | Низкий |
| Некорректный анализ данных | Средняя | Среднее | пользовательская проверка | вывод источников и reasoning | Средний |

---

# Политика логирования

Система должна сохранять следующие логи:

- пользовательские запросы
- действия агента
- вызовы инструментов
- ошибки системы
- время выполнения pipeline

Логи используются для:

- отладки системы
- анализа производительности
- улучшения качества ответов агента

---

# Работа с персональными данными

Если система обрабатывает пользовательские данные:

- данные не должны передаваться внешним сервисам без разрешения
- чувствительные данные должны фильтроваться
- доступ к данным должен контролироваться

---

# Защита от Prompt Injection

Используются следующие механизмы защиты:

- анализ пользовательских запросов
- фильтрация вредоносных инструкций
- ограничение доступа агента к системным инструментам
- проверка источников информации

---

# Подтверждение действий

Если агент выполняет потенциально опасные действия:

- пользователь должен подтвердить действие
- система должна показать объяснение действия
